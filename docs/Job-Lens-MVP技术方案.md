# Job Lens MVP 技术方案

## 目标

将 Job Lens 收敛为一个“上海产品经理岗位筛选工作台”：网站展示已经 OCR 和规则处理后的岗位，用户通过搜索、方向、匹配度和评分筛选岗位，最后点击 BOSS 原始详情链接投递。

## 数据边界

网站使用单一扁平岗位记录，不展示截图、OCR 状态或采集证据。采集数据库、截图和 OCR 中间文件留在离线处理目录，网站只接收最终 `data/jobs.json`。

每条岗位记录包含源岗位字段：岗位名称、公司、城市、区域、办公地点、薪资、经验、学历、公司规模、融资阶段、行业、招聘者、标签、职责、任职要求、JD、采集时间和 BOSS 详情链接。

网站结论字段仅包含：推荐结论、综合评分、产品大方向、职责匹配度、岗位名称匹配度。产品形态、产品层级、城市匹配度、职业发展价值、风险、匹配理由、排除原因、缺失信息、面试问题和投递动作不进入网站展示模型。

推荐结论为：`优先推荐`、`可以考虑`、`谨慎评估`、`不推荐`、`信息不足`。信息不足用于避免对 OCR 或 JD 不完整的岗位做虚假评分。

## 工程结构

```text
app/page.tsx                 页面组合和交互状态
app/globals.css              页面视觉系统和响应式布局
data/jobs.json               当前发布岗位数据
lib/job-types.ts             后续抽离的类型定义
lib/job-filter.ts            后续抽离的筛选与排序逻辑
scripts/build-site-jobs.mjs  OCR/评分结果到网站数据的转换入口
scripts/validate-site-jobs.mjs 数据校验入口
```

MVP 继续使用静态 JSON，不启用 D1；`.openai/hosting.json` 保持原样。后续需要多轮更新、跨设备编辑或投递记录时，再引入 D1。

## 页面能力

- 顶部统计：全部、优先推荐、可以考虑、谨慎评估、不推荐、信息不足；
- 搜索岗位名称、公司和 JD 摘要；
- 按推荐结论、产品方向、最低评分、职责匹配度、岗位名称匹配度筛选；
- 岗位卡片展示源岗位关键信息、结论、评分和两个跳转按钮；
- 右侧详情抽屉展示完整岗位信息、职责、任职要求和 BOSS 投递链接；
- JSON 导入入口保留为下一轮数据替换的接口。

## 数据更新流程

```text
BOSS 采集截图/链接
  -> OCR
  -> 字段标准化
  -> 规则分类和评分
  -> scripts/build-site-jobs.mjs
  -> data/jobs.json
  -> npm run build
  -> 私有 Sites 发布
```

所有链接按 BOSS 岗位 ID 或规范化 `job_detail` URL 去重。未知字段使用 `unknown`，禁止从公司名称、搜索摘要或截图之外推断信息。

## 验收标准

1. 页面不再包含原有示例岗位；
2. 当前数据集包含 100+ 个岗位和对应 BOSS 详情链接；
3. 所有卡片可搜索、筛选和排序；
4. 详情抽屉和 BOSS 投递链接可以打开；
5. 处理层不展示已约定移除的字段；
6. 数据文件通过唯一 ID、链接和推荐枚举校验；
7. `npm run build`、现有测试和采集数据校验全部通过；
8. 私有 Sites 绑定和访问策略不变。
